## Context

Поведение задано в proposal.md и specs/card-deletion/spec.md. Разведка: App получает список через fetchCards и ключ запроса ["cards"]. NewCardForm использует useMutation и invalidateQueries при успехе. BoardColumn передаёт в BoardCard только title и isDone: для удаления нужно также передать id. В api/cards.ts есть GET и POST, функции DELETE ещё нет. В Vite настроен прокси /api → json-server на порту 3001; json-server хранит cards в db.json и поддерживает DELETE /cards/:id.

## Goals / Non-Goals

**Goals:** переиспользовать API-слой и жизненный цикл серверного состояния; удалять по id, не по названию; локализовать состояние запроса и ошибку в карточке.

**Non-Goals:** отдельный backend, массовое удаление, корзина и отмена уже подтверждённого удаления, собственная библиотека модальных окон.

## Decisions

- Добавить deleteCard(id): Promise<void>; выполнить DELETE по encodeURIComponent(id), проверить response.ok, не разбирать JSON. Это корректно и для 204 с пустым телом.
- Передать id в BoardCard из BoardColumn. Мутацию разместить в BoardCard, обновлять список через invalidateQueries(["cards"]) после успеха. Пока запрос не завершён, кнопка disabled; ошибка выводится рядом с карточкой через role="alert".
- Не удалять карточку оптимистично. Альтернатива с немедленным изменением кэша требует отката и обработки гонок, что избыточно для задачи. Карточка исчезнет после подтверждённого успеха и обновления списка.
- Использовать window.confirm с названием карточки. Альтернатива — собственный диалог: больше кода, требуется управление фокусом. Альтернатива без подтверждения отклонена из-за случайного необратимого удаления; это решение явно внесено в спеку до реализации.
- Кнопка — нативный button с видимым текстом и aria-label с названием карточки. Зачёркивание выполненной карточки применять к тексту названия, чтобы не зачёркивать действие удаления.

## Risks / Trade-offs

- Сеть может оборваться после обработки DELETE сервером → ошибка не скрывает карточку локально; после обновления списка отображается серверная истина. Сценарий конкурентного удаления другим клиентом вне задачи.
- GET после успешного DELETE может завершиться ошибкой → React Query сохраняет прежние данные до успешной загрузки; гарантии мгновенного обновления предполагают доступный сервер.
- Нативное подтверждение блокирует страницу и не стилизуется → приемлемо для одного простого действия, без дополнительной зависимости.
- Нет Chromium в среде агента → проверки UI студенткой фиксируются отдельно от сборки, линтера и API-тестов.

## Migration Plan

Миграция данных не нужна. Для проверки использовать копию db.json, не удалять учебные данные. Откат — вернуть коммиты реализации; уже удалённые записи откат кода не восстанавливает.
